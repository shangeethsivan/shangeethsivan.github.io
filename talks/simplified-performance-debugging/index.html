03 · Snapdragon 8 Gen 3

Eight cores. Three kinds.

Count is the picture: one prime, five performance, two efficiency. The GPU is a different chip.

3:50 – 4:50

Show the eight tiles first. Click once. Kuri asks, “Who picks the core?” Anyone? The kernel scheduler. CFS, the Completely Fair Scheduler, shares CPU time between runnable threads. EAS, Energy Aware Scheduling, sits on top and picks a big or little core. Kernels from 6.6 on replace CFS with EEVDF, Earliest Eligible Virtual Deadline First; same job, newer rules. nice is the Linux priority, −20 to +19. Lower means more important, so more CPU time. Android’s presets sit on that scale: THREAD_PRIORITY_DISPLAY is −4, DEFAULT is 0, BACKGROUND is +10. It is a hint, not a guarantee. Do not invent a speed ratio. The tiles are a count. Say X4, five A720, two A520. The draft said X1. It is X4 on the 8 Gen 3. CFS versus EEVDF only if asked. GPU is one sentence. Click again to leave.

05 · Three names for late

Jank. Frozen frame. ANR.

Jank

A frame misses its budget, 16ms at 60Hz. You see a stutter.

Frozen frame

One frame takes longer than 700ms. The app looks stuck.

ANR

The main thread does not answer input for 5 seconds. Android offers to close the app.

Android vitals counts all three. The usual cause is the same: work on the main thread.

5:30 – 6:05

One line each, left to right, while the bar sweeps. Jank: a frame past its budget, the stutter from the last slide. Frozen frame: a single frame over 700ms. ANR: Application Not Responding, the main thread has not answered input for 5 seconds and the system shows the dialog. The scale is logarithmic, so the zones are not to size. Play Console’s Android vitals reports slow rendering, frozen frames, and ANR rate. All three start as work on the main thread, which is what the trace shows you next.

Hard cut. Read the headline, then profileable, then the manifest. shell true is the part that matters. enabled defaults to true from API 30.
